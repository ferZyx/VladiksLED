# Деплой VladiksLED по OTA

Прошивка одна (`env:d1_mini`), веб-UI вшит в неё (`src/webpage.h`, PROGMEM) — отдельной заливки файловой системы нет: обновили UI → залили прошивку → UI обновился.

## Когда запускать

Только по явной просьбе пользователя собрать/залить. Скилл сам по себе не разрешение прошивать — если просили «только собрать», используйте `--build`.

## Шаги

1. **Проверить рабочую копию.** `git status --short`. Если там чужие незакоммиченные правки (параллельная сессия) — сказать пользователю, что они попадут в прошивку, и спросить, прежде чем заливать.
2. **EEPROM-риск.** Если в диффе с прошлой прошитой версией меняется раскладка `LEDState` (`TOTAL_MODES`, `TOTAL_BACKLIGHT_MODES`, `MAX_BACKLIGHT_COLORS`, поля в `src/led_state.h`), убедиться, что повышен `EEPROM_VERSION` и есть миграция в `loadLEDState()`. Иначе на устройстве будут мусорные настройки или сброс к дефолтам — предупредить пользователя до заливки.
3. **Деплой одной командой** (Bash с отключённой песочницей — см. ниже):
   ```bash
   .claude/skills/deploy/deploy.sh
   ```
   Скрипт: собирает → печатает RAM/Flash и число предупреждений → проверяет, что устройство отвечает по HTTP → шьёт через espota → ждёт перезагрузки → печатает `uptimeMs`, `timeValid`, `freeHeap` и др. из `/api/debug`.
   - Только сборка: `.claude/skills/deploy/deploy.sh --build`
   - Только проверка живого устройства: `.claude/skills/deploy/deploy.sh --verify`
4. **Отчёт пользователю:** размеры RAM/Flash (сравнить с базой в памяти Serena `code_style_and_conventions`), результат OTA, маленький `uptimeMs` как доказательство перезагрузки, `timeValid`, `freeHeap`. Если что-то не проверено — сказать прямо.

## Важные детали

- **Песочница.** espota шлёт UDP-приглашение на порт 8266 и ждёт входящее TCP-соединение от платы. В песочнице Bash это блокируется → `[ERROR]: No Answer`, хотя HTTP до устройства работает. Заливку (и сам скрипт целиком) запускать с отключённой песочницей.
- **Адрес устройства** берётся из `upload_port` в `platformio.ini` (`upload_protocol = espota`). Пароля OTA нет.
- **Логи** — `temp/deploy-build.log`, `temp/deploy-upload.log`.
- **PlatformIO** на Mac — через pipx (`~/.local/bin/pio`). Если не установлен: `pipx install platformio`, затем `pio pkg install -e d1_mini` (ставит платформу и библиотеки без сборки).
- **Первая прошивка / плата не в сети** — OTA невозможна, нужен USB:
  ```bash
  pio run -e d1_mini -t upload --upload-port /dev/cu.usbserial-XXXX
  ```
  с временным `upload_protocol = esptool` (не коммитить эту правку `platformio.ini`).
- **`src/config.h`** содержит WiFi-креды — не выводить их значения в отчёты и коммиты.

## Типовые проблемы

| Симптом | Причина / действие |
|---|---|
| `No Answer` при живом HTTP | песочница или файрвол блокируют UDP 8266 → перезапуск без песочницы |
| Устройство не отвечает по HTTP | плата выключена/не в WiFi → проверить питание, Serial (`pio device monitor -b 115200`), при необходимости USB |
| После прошивки не поднялась > 60 с | крэш-луп: смотреть Serial, `Reset Reason` в логе `/ws/logs`; откат — прошить предыдущий коммит |
| `timeValid=false` | NTP ещё не успел или нет DNS; см. раздел «Время» в `CLAUDE.md` |
