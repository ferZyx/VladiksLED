Conventions: avoid direct EEPROM writes in request handlers/hot paths; set settingsChanged=true and let main loop persist (debounced, see `mem:web_stability_and_diagnostics`). Do not add request throttling or verbose per-request logging; UI requests are serialized client-side. Auto-switch mode transitions should not be saved to EEPROM. Keep specific API routes before generic ones (e.g. /api/mode/settings before /api/mode). For chunked POST handlers preserve complete-body guard if (index + len != total) return before JSON parse. Keep mode wiring synchronized across config.h, led_modes.h/.cpp, main.cpp MODE_NAMES, and webpage.h labels. Backlight mode wiring synchronized across config.h, led_modes.cpp runBacklightMode(), and webpage.h.Flash/RAM budget: do NOT enable -DASYNCWEBSERVER_REGEX (no regex routes; it pulls std::regex + libstdc++ locales, ~150-180 KB flash). Log literals go through F(): LOG_PRINT(F("...")) / LOG_PRINTLN(F("...")); LOG_PRINTF fmt must be a string literal (macro wraps it in PSTR + snprintf_P). On ESP8266 plain literals land in .rodata = DRAM. Baseline after this (2026-11-24): RAM 50.0% (40992 B), Flash 49.8% (520584 B).
